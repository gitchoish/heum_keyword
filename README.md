# 혜움 세무기장 마케팅 성과 실시간 웹 대시보드

본 프로젝트는 혜움 세무기장 광고 집행 성과 및 브랜드 키워드 지표를 실시간으로 모니터링하고 분석할 수 있는 웹 기반 대시보드입니다. 백엔드 서버 없이 GitHub Pages를 통해 정적 웹 호스팅으로 즉시 배포되며, 팀원 간 URL 공유가 가능합니다.

---

## 1. 주요 기능

1. **클라이언트 사이드 실시간 연산 엔진**
   - 별도의 데이터베이스나 서버 없이 브라우저 메모리(SheetJS 및 순수 JS 연산)에서 4만여 행의 데이터를 0.5초 이내에 필터링 및 집계합니다.
   - 기간 설정(시작일~종료일 달력 및 빠른 선택 버튼)에 따라 모든 지표가 즉각 재연산됩니다.

2. **간편한 Raw 데이터 갱신 (2가지 방식 지원)**
   - **엑셀 복사/붙여넣기**: 엑셀의 '통합_raw' 시트에서 데이터를 복사(Ctrl+C)한 후 모달 창에 붙여넣기(Ctrl+V)하여 즉시 반영.
   - **파일 드래그 앤 드롭**: 엑셀 파일(`.xlsx`, `.csv`)을 브라우저에 끌어다 놓으면 자동 파싱 및 갱신.
   - 갱신된 데이터는 브라우저 로컬 저장소(LocalStorage)에 자동 보관되어 페이지를 새로고침하거나 브라우저를 다시 열어도 유지됩니다. 언제든지 '기본 데이터로 초기화' 버튼을 눌러 원본 상태로 복구할 수 있습니다.

3. **6대 핵심 분석 탭 구성**
   - **종합 대시보드**: 총 광고비(VAT 제외/포함), 소진율, 유입 클릭수, 리드수, 유효리드수, 수임건수, 리드 CPA, 수임 CPA 등 핵심 KPI 카드 및 매체별 성과 요약 테이블.
   - **브랜드 키워드 분석**: 4대 키워드 분류 체계(브랜드 자산군, 핵심 직무군, 컨설팅군, 로컬 타겟군) 기준 성과 분석.
   - **일별 키워드 추이**: 매체 선택 및 키워드 검색 후 일자별 노출/클릭/비용/리드/수임 성과를 보여주는 31일 캘린더 엔진.
   - **주차별 추이 비교**: 주차별(W36~W40) 성과 및 전주 대비(WoW) 증감률 분석.
   - **월별 추이 비교**: 9월 vs 10월 월별(MoM) 실적 비교.
   - **매체별 상세 분석**: 6대 매체(네이버 검색광고, 구글 검색광고, META, 네이버 GFA, 네이버 플레이스, 브랜드검색광고) 탭 전환 및 상위 10대 키워드/소재 랭킹 테이블.

4. **100% 정량적 팩트 기반 구성**
   - 주관적 추정이나 임의의 텍스트 분석을 배제하고, 원천 데이터(`통합_raw`)에서 확인 가능한 정량적 수치와 순수 수식(SUMIFS/IF 원리)만으로 구축되었습니다.
   - 혜움 비즈니스 규격의 다크 네이비 UI 테마(#1F4E79, #0F2439)가 적용되어 있습니다.

## 2. 파일 구성

- `index.html`: 대시보드 UI, 연산 로직, 차트 시각화, 모달이 통합된 단일 웹 애플리케이션 파일.
- `data.js`: 기본 원천 데이터 42,699행이 내장된 데이터 파일 (초기 로딩 시 사용).
- `알프레드_혜움_브랜드키워드_성과리포트.xlsx`: 순수 수식 기반 원천 엑셀 리포트.
- `create_web_app.py`: 웹 대시보드 빌드 스크립트.

## 3. GitHub Pages 배포 가이드

### 단계 1: GitHub에서 새 리포지토리 생성
1. GitHub(https://github.com)에 로그인합니다.
2. 우측 상단 '+' 버튼 클릭 후 **New repository**를 선택합니다.
3. Repository name 입력 (예: `heum-marketing-dashboard`)
4. Public(공개) 또는 Private(비공개 - GitHub Enterprise/Pro 플랜의 경우 Pages 지원)을 선택합니다.
5. 'Initialize this repository with' 항목들은 모두 체크 해제하고 **Create repository** 버튼을 클릭합니다.

### 단계 2: 로컬 저장소 연결 및 푸시
터미널(PowerShell 또는 Git Bash)에서 현재 디렉토리 위치로 이동 후 아래 명령어를 순서대로 실행합니다:

```bash
# 1. 원격 저장소 주소 연결 (본인의 리포지토리 URL로 변경)
git remote add origin https://github.com/[사용자계정]/[리포지토리명].git

# 2. main 브랜치로 최신 코드 푸시
git push -u origin main
```

### 단계 3: GitHub Pages 활성화
1. 생성한 GitHub 리포지토리 페이지에서 상단 **Settings** 탭을 클릭합니다.
2. 좌측 메뉴에서 **Pages**를 클릭합니다.
3. **Build and deployment** > **Source** 항목을 `Deploy from a branch`로 설정합니다.
4. **Branch** 항목에서 `main` 브랜치 및 `/ (root)` 폴더를 선택하고 **Save** 버튼을 클릭합니다.
5. 약 1~2분 후 상단에 배포 완료 알림과 함께 배포된 웹사이트 URL(예: `https://[사용자계정].github.io/[리포지토리명]/`)이 생성됩니다.
6. 해당 URL을 복사하여 사내 팀원들에게 공유하면 즉시 웹에서 대시보드를 열람할 수 있습니다.

## 4. 매일 최신 Raw 데이터 반영하는 방법

1. 사내 로컬 환경에서 신규 Raw 데이터가 포함된 엑셀 파일을 준비합니다.
2. 브라우저에서 대시보드 웹페이지(GitHub Pages URL)를 엽니다.
3. 우측 상단의 **[Raw 데이터 갱신]** 버튼을 클릭합니다.
4. 아래 두 가지 방식 중 편한 방법을 선택합니다:
   - **방식 A**: 엑셀 시트(`통합_raw`)에서 복사한 데이터를 모달 입력창에 붙여넣고 [데이터 파싱 및 대시보드 갱신] 클릭
   - **방식 B**: 최신 엑셀 파일(`.xlsx`)을 점선 영역에 끌어다 놓기(Drag & Drop)
5. 팝업 알림과 함께 브라우저 화면의 6개 탭 전체 지표가 즉시 최신 데이터 기준으로 재계산됩니다.
6. 브라우저 로컬 저장소에 저장되므로, 이후 페이지를 새로고침해도 반영된 최신 데이터가 유지됩니다.
